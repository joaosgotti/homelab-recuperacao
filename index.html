1. Primeiro, qual é o caso?

  1. O servidor liga, mas algo quebrou (configuração ruim, atualização): no próprio servidor leia ~/RESTAURAR.md (Timeshift, volta o sistema sem tocar em mídia) ou restaure só a pasta que quebrou com o restic (passo 2).
  2. O disco interno (NVMe) morreu, ou o notebook se foi: siga os passos 2 a 5 numa máquina nova com Ubuntu 24.04.
  3. Só o HD externo morreu: nada se perde; a mídia original está no HD interno (/mnt/midia). Compre outro, formate ext4 com rótulo espelho e o rsync das 04:00 refaz a cópia.

2. Restaurar os dados do backup offsite (restic + Backblaze B2)

sudo apt update && sudo apt install -y restic
export RESTIC_REPOSITORY='<endereço do repositório>'
export B2_ACCOUNT_ID='<key ID do B2>'
export B2_ACCOUNT_KEY='<application key do B2>'
restic snapshots          # pede a senha do restic; o último da lista é o mais recente
restic check              # tem que terminar com "no errors were found"
sudo mkdir -p /restaurado
sudo -E restic restore latest --target /restaurado

Tudo volta em /restaurado com os caminhos originais. Para uma pasta só, acrescente --include /caminho. O passo a passo detalhado também está no backup, em /restaurado/home/joao-server/RECUPERAR-BACKUP.md, e os relatórios de como cada coisa foi montada estão em /restaurado/home/joao-server/logs-homelab/.

3. Reinstalar os serviços

Instale o Ubuntu 24.04, dê o IP fixo 192.168.15.200 (Wi-Fi, gateway 192.168.15.1) e o nome joao-server. Então, para cada serviço: instale o programa, pare-o, copie a configuração de /restaurado para o mesmo caminho e ligue de novo. As units do systemd estão em /restaurado/etc/systemd/system/ e os scripts em /restaurado/usr/local/{bin,sbin}.

Serviços nativos

  • Pi-hole: curl -sSL https://install.pi-hole.net | bash, depois copie /etc/pihole restaurado
  • Jellyfin: repositório apt oficial (/etc/apt/sources.list.d/jellyfin.list está no backup), apt install jellyfin
  • Radarr: binário em /opt/Radarr (baixe de radarr.video), dados em /var/lib/radarr
  • Sonarr: binário em /opt/Sonarr (sonarr.tv), dados em /var/lib/sonarr
  • Prowlarr: binário em /opt/Prowlarr (prowlarr.com), dados em /var/lib/prowlarr
  • Bazarr: git clone em /opt/bazarr + venv; dados em /opt/bazarr/data
  • Transmission: apt install transmission-daemon; config em /etc/transmission-daemon
  • Uptime Kuma: git clone em /opt/uptime-kuma + npm run setup; dados em /opt/uptime-kuma/data
  • Tailscale: repositório apt oficial, tailscale up com a sua conta
  • Concierge: código e venv em /opt/concierge (no backup; recrie o venv)
  • Ollama: curl -fsSL https://ollama.com/install.sh | sh; modelos se baixam de novo
  • Docker: apt install docker.io docker-compose-v2
  • Samba: apt install samba; config em /etc/samba

4. As RAGs (MCPs dos cursos)

  1. Copie de /restaurado/home/joao-server/ para /home/joao-server/: backups/rag-cin, rag-ia-aplicada, rag-idv, rag-idv-funnel e .config/systemd/user.
  2. Recrie o ambiente Python: 
    python3 -m venv ~/rag-cin-mcp/.venv
~/rag-cin-mcp/.venv/bin/pip install -r ~/backups/rag-cin/rag-cin/requirements.lock.txt
  3. Entre no Tailscale. As units ouvem no IP Tailscale do servidor; se ele mudar, troque nas units rag-*-mcp.service.
  4. sudo loginctl enable-linger joao-server
systemctl --user daemon-reload
systemctl --user enable --now carteira-google.timer rag-cin-mcp.service rag-ia-aplicada-indexar.timer rag-ia-aplicada-mcp.service rag-idv-mcp.service

5. O que NÃO está no backup

  • Mídia (/mnt/midia: filmes, séries, músicas e os vídeos dos cursos). Só existe no HD interno e no espelho, que fica no mesmo notebook.
  • Áudio e vídeo das RAGs, e o ambiente Python (recriável).
  • As capas e imagens do Jellyfin (/var/lib/jellyfin/metadata): ele baixa de novo sozinho. O banco, os usuários, o histórico e as bibliotecas estão no backup: instale o Jellyfin, pare-o, copie /restaurado/var/lib/jellyfin e /restaurado/etc/jellyfin e ligue.
  • A partição cifrada de 372 GB do HD externo.
